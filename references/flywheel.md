# 一库一站一号：内容飞轮（IMA 素材进出 + 公众号双出口 + 30 天台账）

> 对 WorkBuddy 说「找素材」「发文章」「飞轮」「联动公众号」「30 天计划」时读本文。
> 这是第二期工作坊的核心目标：**库（ima）→ 网站 + 公众号（双出口），一篇素材两处发，文章再回存库**。

## 全景图

```
        ┌─────────────┐
        │  ima 知识库  │←──────────────┐
        │ （第一期的库）│               │ 回存：发布后的文章归档
        └──────┬──────┘               │
       素材两通道↓                    │
        ┌─────────────┐    发布       │
        │  一篇文章    │──────→ 网站（GitHub Pages，本技能管线）
        │ new_post.py │──────→ 公众号（粘贴版 / API 草稿箱）
        └─────────────┘
              ↓
        _local/flywheel-ledger.md（30 天台账：写了什么/读者要什么/下一步）
```

## 素材两通道（从库里挖）

| 通道 | 适用 | 怎么做 |
|------|------|--------|
| **粘贴通道**（零配置，人人可用） | ima 里的一段笔记、公众号收藏、读书摘录 | 复制素材文字 → 对 WorkBuddy 说「用这段素材帮我在网站上发一篇文章：<粘贴>」 |
| **查库通道**（第一期学员优先） | 知识库里成体系的素材 | 已配 ima-mcp 连接器或 `~/.config/ima/` 凭证 → 对 WorkBuddy 说「从我的 ima 知识库找关于<主题>的素材写一篇」 |

规则：
- **Truth-first**：素材里没有的，不编。引别人观点注明「某某说」。
- 素材太薄（<100 字）先问用户要更多，别硬凑字数——薄素材宁可直接发短文，短文也是更文。
- 一次只用一个主题的素材；两个主题就拆成两篇（库存+1）。

## 写作规范（new_post 之前，WorkBuddy 按这里把关）

- 标题 ≤ 20 字，说人话，不用冒号套路
- 开头 3 行内进入正题（不写「在这个信息爆炸的时代」）
- 小标题分节（##），每节 ≤ 200 字；要点用列表；金句用 >
- 结尾一段「怎么办」+ 一句 CTA（自动带站名+公众号引导，模板已内置）
- 全文 800-1500 字为宜；配图可后补，别让图挡住发布

## 双出口（一篇文章两处发）

### 出口 1 · 网站（主出口）

`python3 scripts/new_post.py` 生成：
- `posts/<日期>-<slug>.html` —— 网站文章页
- 更新 `posts.js` —— 首页列表自动出现
- 然后按 `references/publish.md` 更新线上

### 出口 2 · 公众号

**默认（粘贴版，人人可用）**：
1. 打开 `_local/wechat-<日期>-<slug>.html`（全内联样式，专为公众号编辑器准备）
2. Cmd/Ctrl+A 全选 → 复制 → 粘贴进 mp.weixin.qq.com 编辑器
3. 检查标题/封面 → 存草稿 → 你来定什么时候群发（**技能绝不自动群发**）

**升级（API 推草稿箱，需兄弟技能）**：
- 已装 rsi-wechat-publisher 且配过 `~/.config/wechat/` 凭证 → 对 WorkBuddy 说「把这篇也推到公众号草稿箱」
- 兄弟技能的 format/qa 环节会做排版和质检，推完你仍人工确认群发

### 回存：文章回 ima（库越用越厚）

发布后对 WorkBuddy 说「把这篇文章归档回我的 ima」：
- 有 ima-mcp：直接入库，归入「发文归档」目录

### 反馈回流：QQ 邮箱 → ima「网站邮箱信息」（v2.3，闭环最后一环）

网站页脚和每篇文章末尾都有 QQ 邮箱反馈入口（`config.js` 的 `feedback_email`）。读者来信按下面流程回流知识库：

1. **配置**（一次性）：`~/.config/ima/email.json` 填 QQ 邮箱 IMAP 授权码（QQ 邮箱设置里开启 IMAP 并生成授权码）。
2. **拉取**：对 WorkBuddy 说「**拉网站反馈**」，或跑 `python3 scripts/feedback_pull.py`（默认近 7 天；`--dry-run` 先看不动库）。
3. **归档**：每封信自动入 ima「**网站邮箱信息**」目录（首次自动建），模板含「下一轮迭代信号」摘要栏——WorkBuddy 补写读者想要什么/哪里坏了/什么值得加。
4. **消化**：飞轮周报对账时，把「网站邮箱信息」目录里"待处理"状态的信纳入选题（读者问得多的优先）。

红线：邮箱只读（IMAP readonly，绝不删信）；来信原文逐字保留（R2 证据真实性）。

### 兴趣雷达：站内兴趣 → 全网热点 → ima「热点选题」（v3.0，主动选题流）

反馈回流是「读者拉」，兴趣雷达是「热点推」——两流在 ima 汇成同一池选题：

```
站内文章标题(posts.js) ─┐
                       ├→ 兴趣关键词 → 微博/知乎/抖音/头条四榜（开源 60s API）
ima「网站邮箱信息」反馈 ─┘                  │
                                           ↓
                              命中热点 → ima「热点选题」目录（按热度排序）
                                           ↓
                     周报翻目录 → 「用这个素材发一篇」→ 站+号双出口 → 回存 ima
```

- **跑雷达**：对 WorkBuddy 说「**扫热点选题**」，或 `python3 scripts/interest_radar.py`（`--save` 输出 ima 入库指令流；`--keywords "AI,拆书"` 手动补词；`--list-sources` 看数据源）。
- **关键词来源**：站内 `posts.js` 文章标题自动提取 + `~/.config/ima/feedback-mirror.json`（feedback_pull 的本地镜像，可选）+ 手动补词；词表扩展见脚本 `TOPIC_EXPANSION`（泛化匹配，小而精防误命中）。
- **节流红线**：开源接口限流，脚本内建 6s 间隔；单榜拉取失败跳过不判故障（R3 抖动口径），四榜全挂才报错。
- **消化**：周报新增第五步——翻 ima「热点选题」目录，挑 1-2 条高热度且站内有素材支撑的，进下周选题池（与「读者问得多的」取交集优先）。
- **版权红线**：热点标题+链接做选题线索，正文必须用站内/库内自有素材创作，不搬运热榜正文。


### 回存的降级路径

- 无连接器：把文章链接+三行摘要记进 `_local/flywheel-ledger.md` 的归档区，下次攒一批手动存

## 30 天飞轮台账（`_local/flywheel-ledger.md`）

向导不生成它；第一次发文章时由 new_post 流程创建（WorkBuddy 代管）。格式：

```markdown
# 内容飞轮台账（开始于 <日期>）

## 本周（W<n>）
- 发文：站 <n> 篇 / 号 <n> 篇 / 回存 <n> 篇
- 读者问得最多的：<…>
- 下周想写：<主题>（素材在 ima 的<位置>）

## 归档
- <日期> 《<标题>》 站✓ 号✓ 回存✓
```

每 7 天对 WorkBuddy 说「飞轮周报」：读台账 → 对账（站上几篇/草稿箱几篇/库回存几篇）→ 翻选题双源（ima「热点选题」目录 + 「网站邮箱信息」待处理反馈）→ 给出下周选题建议（优先三重交集：**读者问得多的 × 雷达命中的热榜 × ima 里素材厚的**）。周报第一步先说「扫热点选题」刷新雷达数据。

## 30 天节奏建议（工作坊带走即执行）

| 周 | 站 | 号 | 动作 |
|----|----|----|------|
| W1 | 2 篇 | 2 篇 | 跑通双出口，不求好只求通 |
| W2 | 3 篇 | 3 篇 | 建立节奏；开始记台账 |
| W3 | 3 篇 | 3 篇 | 复盘数据，砍掉没人看的栏目 |
| W4 | 4 篇 | 4 篇 | 稳定输出；给蓝本式升级（自定义域/互动）立项 |

一个月后你就有了：一个 12+ 篇文章的网站、一个持续更新的公众号、一个越滚越厚的知识库——这就是「一库一站一号」。
