# 写文章执行手册（new_post.py 的人机分工）

> WorkBuddy 在执行「发文章」类请求时按本文操作；人直接跑脚本时本文可跳过。

## 分工

- **人（WorkBuddy 对话）做的**：定标题、给素材、把关事实与口吻
- **脚本做的**：Markdown→HTML、文章页/公众号版生成、posts.js 维护——**不要手写这些文件**

## 执行步骤

1. **收素材**：用户粘贴 / 指文件 / 从 ima 查（flywheel.md 素材两通道）
2. **把关**（不过关先改再进管线）：
   - flywheel.md「写作规范」过一遍：标题、开头、分节、长度
   - 隐私红线：身份证/手机号/住家地址/未公开收入/他人隐私 → 删除或化名
   - 事实红线：素材没有的不编；引述注明来源
3. **起文件名 slug**：标题转小写、空格转 `-`、只留中英文数字和 `-`，≤40 字符（`make_slug` 规则）
4. **跑管线**：
   ```bash
   python3 <skill目录>/scripts/new_post.py --site <站点目录> --title "<标题>" --file <素材临时文件>
   ```
   （素材来自对话时先写进 `/tmp` 临时 .md 再 `--file` 传入）
5. **验收产物**：向用户报告三个产物路径；提醒公众号版在 `_local/`（不上传）
6. **发布**：用户确认 → 按 publish.md 对应通道更新线上（git 通道直接 push；网页通道给出待上传清单）

## 同日多稿

- 同一天第二篇：`--slug` 里脚本会自动处理重名（日期前缀相同、slug 不同即可），无需干预
- 改已发布的文章：改 `posts/<文件>.html` 源文件 → 重新发布；**不要**改 `posts.js`（它只管清单，正文以 posts/ 文件为准）

## 红线回顾（违反任何一条即停）

1. `_local/` 不上传
2. 凭证不进站点目录、不进提示词
3. 不代替用户群发公众号（草稿箱是终点站）
4. 素材不足不硬写——退回问用户要素材
