# 自动化闭环设计（v2）——从工作坊产出到站点自愈

## 总图

```
        ┌────────────────────────────────────────────────────────┐
        │                     IMA 知识库（库）                     │
        └──────┬──────────────────────────────┬──────────────────┘
               │ WorkBuddy 技能                │ WorkBuddy 技能
               ▼                              ▼
     ┌──────────────────┐            ┌──────────────────┐
     │  一期：公众号（号） │            │  二期：网站（站）   │
     │  九步内容流水线    │            │  建站/发文/部署    │
     └────────┬─────────┘            └────────┬─────────┘
              │ 草稿箱（人工点发）               │ push main
              ▼                              ▼
     ┌──────────────────┐            ┌──────────────────┐
     │  公众号后台        │            │  GitHub Actions   │
     └──────────────────┘            │  自动构建+部署     │
                                     └────────┬─────────┘
                                              ▼
                                    ┌──────────────────┐
                                    │ site_check 线上体检 │◄─── 每日 09:17
                                    │ （只读，6 项）       │     site-ops Actions
                                    └────────┬─────────┘
                                             ▼
                                   ┌───────────────────┐
                                   │  RSI 台账（_rsi_ledger）│
                                   │  体检历史/坏链教训/节奏  │
                                   └────────┬──────────┘
                                            ▼
                                   下一轮选题·建站·体检改进
```

## 分步讲解

1. **产出**：学员在 IMA 知识库沉淀拆书笔记；WorkBuddy 技能把库内容变成两出口产物——公众号文稿（一期）与站点文章（二期 `new_post.py`）。
2. **提交**：站点文章 push main（或 PR）；每篇文章一个 commit，可追溯。
3. **构建部署**：GitHub Actions 自动构建部署（chai 站即此模式：push main → vite build → Pages）。
4. **线上体检**：`site_check.py` 只读检查 6 项——主站 200+title、chailive 首页、chailive 书目页（含 riaComplete）、chaibuddy 首页与 people.json、AI 代理健康（/cl2-ai/ping 回 ok:true）。每日 09:17（北京）由 site-ops Actions 定时执行，失败输出中文告警块。
5. **回流 RSI 台账**：体检结果（过/挂、耗时、坏链）增量记入 `_rsi_ledger.md`——同一家台账同时服务号与站，这是「一库一站一号」闭环的闭合点。
6. **改进**：下一轮按台账教训改进（如坏链高发路径加预检、内容节奏按读者数据调整）。

## 与一期九步流水线对照

| 一期九步（号） | 二期对应（站） | 说明 |
|---|---|---|
| 1 热点采集 | （站点不需要，内容同源） | 库内素材两出口共用 |
| 2 素材整理 | post 草稿 | `new_post.py` 接力 |
| 3 选题 | 同一 RSI 选题器 | 台账共享 |
| 4 写作 | post 正文写作 | 同源不同排版 |
| 5 质检 ≥85 | 线上体检前置检查 | site_check 的前体 |
| 6 排版 | 模板渲染 | site-minimal 模板 |
| 7 草稿箱 | push main（自动部署） | 站侧无需人工点发 |
| 8 git 归档 | git 归档（同一操作） | 完全同一步 |
| 9 回存 IMA | 体检结果回流 RSI | 闭环闭合点 |

## RSI 台账记什么

- **站点体检历史**：每日 overall 与各_check 耗时趋势，慢查询定位。
- **坏链教训**：哪类 URL 最常断（外链 vs 资源 vs API），对应预防动作。
- **内容节奏**：发文频率 vs 阅读/访问数据的对照（号站各自成列）。

## 安全红线（与一期同源）

1. **体检只读**：site_check 永远不写线上内容、不触发部署、不改数据。
2. **不自动改线上**：Actions 只构建部署 push 的内容，不自动生成线上变更。
3. **人工点发保留**：号侧绝不自动群发（一期红线原样继承）；站侧每次上线都有对应人工 commit。
